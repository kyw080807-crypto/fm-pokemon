## 로드맵 (원본의 그림 `img/image1.png`를 글로 옮김)

재미 검증(단계 1)을 통과해야 그림 작업(단계 2부터)을 시작한다. 단계 0~1은 그림 없이 진행한다.
각 단계는 오른쪽 확인 기준을 통과해야 다음 단계로 넘어간다.

| 단계 | 내용 | 확인 기준 |
|---|---|---|
| 0 | 환경 세팅과 데이터 변환 | 데이터가 Essentials에서 읽힌다 |
| 1 | 시뮬 코어(헤드리스) | **180클럽 주간 시뮬이 돌고 순환이 재미있다** (가장 중요한 관문) |
| 2 | 도시 맵 1장과 건물 배치 | 상태 데이터로 건물이 자동 배치된다 |
| 3 | 직접 전투 연결, 1시즌 | 직접 전투와 자동 진행이 시즌에 맞는다 |
| 4 | 관동 한 지방(도시 11곳) | 공유 도시의 협의가 재미있다 |
| 5 | 월드맵, 교통, 원정 | 이동이 성장의 동기가 된다 |
| 6 | 나머지 지방 확장 | 템플릿이 다른 지방에서도 통한다 |

  세계(`FM::World`: 180클럽·9리그를 하루씩 진행 — 리그 날 경기·관중 수입·승리 수당·명성, 리그 종료 상금·재건 지원금,
  매주 월요일 식비·건물/경기장 유지비·굿즈·빚 이자).
  헤드리스: `ruby tools/sim/season.rb [년 수] [시드]` — 180클럽 1년(365일) 약 0.1초.
  남은 것: **AI의 지출·투자**(건물·도시 성장·영입), 스폰서 계약, 도시 공공예산과 협의, 대회, 세이브 연결, 계산식 보정.

### 원본에서 옮긴 경제 공식 (`FM::Economy`)

| 항목 | 공식 (원본 함수) |
|---|---|
| 시작 명성 | 레벨×1.6 + 챔피언 20 / 사천왕 12 / 관장 8 / 원작 트레이너 10, 15~95 (`initFame`) |
| 시작 자금 | 명성 × ₽3,000 |
| 관중 | (500 + 홈 명성×45 + 원정 명성×25×L) × (0.8 + 0.1×최근 5경기 승수), 경기장 정원까지, ±8% (`demand`/`gate`). 원정 몫은 좌석 30%까지(설계 05) |
| 표값 | 3 + 명성×0.03 (`priceRef`) |
| 경기장 | 정원 임대 1,000 / Lv1 2,000 ~ Lv6 30,000, 주 유지비 ₽800 ~ ₽10,000 (`STD`) |
| 승리 수당 | ₽1,500 + 순위가 높은 상대를 이기면 순위 차 × ₽600, 무승부 양쪽 ₽500 |
| 명성 변화 | 승 +0.4(명성 15 이상 높은 상대면 +0.25), 패 −0.15, 리그 종료 (11−순위)×0.6 + 1위 5 |
| 리그 상금 | ₽150,000 − (순위−1)×₽3,158, 15위 이하 재건 지원금 (순위−14)×₽25,000 |
| 식비(사실상 급여) | OVR×1.5 = o → (100 + o²/90 + max(0,o−200)²/8) × 명성 배율(0.6~1.45) (`foodOf`) |
| 건물 유지비 | 60 × (2×레벨)^1.4 — 설계 레벨 1~5를 원본 1~10으로 환산. 원본은 훈련·스카우팅만, 여기선 설계대로 모든 클럽 건물 |
| 굿즈 | 명성^1.6 × 0.6 / 주 |
| 빚 이자 | 마이너스 잔고의 0.5% / 주, 최소 ₽10 |

빠진 것: 스폰서(설계는 계약형), 코치 식비, 원정 친선 투어, 영입·스카우트·투자 지출.

### 시뮬 보정 메모

- 클럽 전력을 "로스터 상위 3종의 종족값 합 평균"으로만 잡으면 초반 관장(덴트 290, 호일 303 등)이 거의 매 시즌 꼴찌다.
  원본 `makeMon`은 레벨에 비례해 노력치를 미리 쌓고(`pretrain`) ★로 개체값을 정하므로, 전력에 노력치·개체값·숙련도를
  넣어야 한다. `FM::MatchSim`의 SCALE·HOME_EDGE·DRAW_RATE도 실제 전투 결과로 보정할 첫 추정치다.
- 지금 수치: 전력 높은 쪽 승률 72%, 무승부 3%, 홈 승률 약 50%(홈 이점이 작다).
- **전력에 개체값·노력치 반영 후**(Lv50에서 능력치 ≈ 종족값 + 개체값/2 + 노력치/8): 꼴찌가 초반 관장에서
  ★ 일반 트레이너로 바뀌었다. 20시즌 평균 순위: 챔피언 1.8, 사천왕 6.3, 관장 12.9, 트레이너 11.2.
- **돈이 쌓이기만 한다**: 클럽당 연 수입 약 ₽68만(관중 44만·상금 12만·수당 4만·굿즈 5만·지원금 3만),
  지출 약 ₽31만(건물 13만·식비 10만·경기장 8만). 20년 뒤 중앙값 ₽690만, 빚진 클럽 0. 원본 AI는 영입·스카우트·
  시설 투자로 돈을 쓰는데 그 부분이 아직 없어서다. 설계의 핵심 순환(돈 → 건물·도시 성장)이 다음 구현 대상.

## 포켓 매니저 원본 데이터

설치본 `%LOCALAPPDATA%\PokeManager\` (Windows판, Neutralino 앱)의 `resources.neu`(asar 형식) 안
`resources/index.html` 한 파일에 게임 코드와 데이터 표가 모두 들어 있다. 추출(결과는 gitignore된 `import/`):

```
ruby tools/pokemanager/asar.rb extract "%LOCALAPPDATA%\PokeManager\resources.neu" import/pokemanager
ruby tools/pokemanager/export.rb      # → import/pokemanager/data/{dex,trainers}.json + 커버리지 보고
```

| 원본 상수 | 내용 (원본 주석 기준) |
|---|---|
| `DEX` | 1025종: 한국어 이름, 타입, 종족값 6개, 진화[[도감번호, 레벨]], 등급(0 일반/1 준전설/2 전설/3 환상/4 UB/5 패러독스), 이전 진화 |
| `TRAINERS` | 지방별 20명 × 9: [역할(C/E1~4/G1~8/T), 이름, 레벨, 스카우팅 시설, 훈련 시설, 잠재력, 로스터 도감번호] |
| `LEARN` | 기술 배우기(레벨·TM·알·튜터), 특성, 지역 폼 |
| 지방 표 | 지방별 시작 스카우팅·훈련 단계와 자금 (`{id, name, scout, train, funds}`) |
| `buildWorld()` | 새 게임 생성: 로스터 레벨 = 트레이너 레벨 ±1, 3마리 미만이면 같은 타입으로 채움, 명성 → 시작 자금(명성×3000)·경기장 |

확인한 사실 (2026-10-27, export.rb 결과):
- 트레이너 180명 = 원작 로스터 156명 + **무작위 로스터 24명**(설계 문서의 ★와 같다). 원본은 무작위 로스터와
  "3마리 채우기"를 새 게임마다 새로 뽑는다.
- **결정(2026-10-27): 고정 시드로 한 번 생성해 데이터로 굳힌다.** 원본 `buildWorld()`를 Node에서 그대로 실행하고
  `Math.random`만 시드 PRNG(mulberry32, 시드 20261027)로 바꿔 생성한다:
  `node tools/pokemanager/lock_rosters.js` → `tools/pokemanager/data/rosters.json`(커밋됨).
  무작위 24명의 로스터 전체 + 원작 로스터가 3마리 미만인 19명의 채우기 포켓몬, 합계 127마리(종·폼·레벨·★·개체값).
  같은 시드는 항상 같은 결과다. 원작 로스터 자체(종)는 `TRAINERS`가 기준이고, 그 레벨·개체값은 여기서 고정하지 않았다.
- 무작위 선택은 15% 확률로 다른 지방의 포켓몬을 뽑아서, 고정된 127마리 중 **9세대 17마리는 팔데아 밖 트레이너에게도 있다**
  (호연 시우, 알로라 윤슬, 가라르 태오). 9세대 플러그인 없이 가려면 이 셋은 시드를 바꾸거나 해당 칸만 다시 뽑아야 한다.
- 로스터에 쓰인 종 중 9세대는 기본 v21.1 PBS(898종, CALYREX까지)에 없었다.
  **→ 2026-10-27 Generation 9 Pack 3.3.8 설치로 해결.** 원작 로스터 + 고정 로스터의 종 438개가 모두
  Essentials ID로 이어지고(9세대 이상 36종 포함), 엔진에 컴파일된 것을 스모크 검사 `roster_gen9_species`로 확인한다.
- 원본 이름은 한국어뿐이다. Essentials 종 ID(영문)는 도감번호로 잇는다: PBS 순서 = 도감번호
  (`pokemon.txt` 1~898 + `pokemon_base_Gen_9_Pack.txt` 899~1025). `ruby tools/pokemanager/species_ids.rb`
- 원본 전투 규칙: **모든 배틀 Lv50**, 엔트리 6마리를 서로 공개하고 3마리를 골라 싸운다. 개체값(★)은 고정,
  노력치는 훈련으로 오른다. → 설계 문서 미결 사항 "직접 전투 룰"의 기준이 될 수 있다.

## 현재 코드와의 차이 (설계에 맞추려면 고칠 것)

- **캘린더 — 결정(2026-10-27): 1년 365일 실제 달력**(월 길이 31·28·31…, 윤년 없음). 한 주에 경기가 두 번인
  주가 있으므로 일정은 주차가 아니라 **날짜**로 잡는다. 주는 월~일이고 해를 넘어 이어지므로 해마다 1월 1일 요일이 하루씩 밀린다.
  `FM::Calendar`에 `date`, `day_of_year`, `date_after`, `days_between`, `days_until` 추가.
  설계 원본의 "N주 7일째 / 더블 주 3·7일째", "1월 전체 = 1~4주" 표현은 날짜 기준으로 고쳐야 한다(원본 갱신 필요).
- **리그 일정 — 결정(2026-10-27)**: 프리시즌 1월 1~31일. 리그 경기는 **일요일**, 2경기 주는 **수요일·일요일**.
  2월 첫 일요일부터 33주(1경기 주 28 + 2경기 주 5 = 38라운드). 2경기 주 위치는 설계 제안(시즌 10·16·22·28·34주
  = 리그 6·12·18·24·30주)을 `FM::Season::DOUBLE_WEEKS`에 두고 시뮬로 조정한다. 구현: `FM::Season.league_dates`.
  예: 1년차 2/4~9/16(수요일 3/7·4/18·5/30·7/11·8/22), 2년차는 요일이 밀려 2/3~9/15.
- **재정**: 설계는 지갑이 둘(클럽 재정, 도시 공공예산)이다. `FM::Finance`는 지갑 하나짜리라
  클럽마다·도시마다 하나씩 두면 된다. 대출(한도·이자), 계약형 스폰서, 위기 단계는 아직 없다.
  통화는 ₽.
- **상태 규모**: `FM::State`는 플레이어 하나의 캘린더+지갑뿐이다. 설계는 세계(도시 100, 클럽 180) 전체를
  저장한다. 단계 1에서 `FM::World` 같은 상위 구조로 바꾸고, 세이브 스키마 버전을 올린다.
- **시작 자금**: `FM::State::START_BALANCE = 10_000`은 자리표시다. 설계는 기존 포켓 매니저의 시작 상태를
  변환해서 정한다.
- **포켓몬 데이터**: ~~9세대 없음~~ → Generation 9 Pack 3.3.8 설치로 1025종 전부 있음(2026-10-27).
